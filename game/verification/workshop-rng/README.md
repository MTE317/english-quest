# 工房ボタンの乱数生成器修正

基準: main `a0974a12099766c666eb2f06ca68d344a401826d` (#167)。2026-11-27検証。

## 原因と範囲

町の `rng` は seed 付き乱数生成器を返す factory。工房の制作・全再付与・数値再抽選だけ factory 自体を渡していたため、抽選側が関数を数値として扱い、効果なしや NaN（JSON保存でnull）になっていた。正常な強化と同様、ボタン操作ごとに `rng()` を一度渡す。抽選式・価格・素材・確率・データIDは変更しない。町HTML→town-page→facility-viewのキャッシュ版を `workshop-rng-1` に更新。

## 回帰テスト

`node --test game/tests/workshop-view.test.js`

実際のworkshopViewが登録するボタンイベントと、町と同じ「factory→seed付き生成器」の契約を使う。修正前は制作/全再付与/数値再抽選の3件が失敗し、修正後は6件成功。生成器の作成回数だけでなく、効果個数・有限値・種類保持・一度だけの費用/素材消費と保存再読込を検査。不足による無効化、表示後の残高不足、強化、分解確認キャンセル/還元、過去の破損値の非復旧も検査。

最新mainの全体は668件中666成功・制作関連2件失敗（先行検証で同じSHAを実行）。これはUIの乱数渡しと別の旧期待値問題：#166で固有候補から2〜4個を抽選する仕様になったのに、専用短剣の毒20固定や防具の特定効果が必ず付くと期待していた。該当2テストだけ、固定seed・有効な候補/個数・抽選された効果の反映へ変更。戦闘での毒/吸血/追撃等の既存テストは維持。修正後の `npm test --prefix game` は **674/674成功**。

## 実ブラウザ

固定checkoutをHTTP配信し、Playwright + Chromiumの新規390px合成コンテキストだけを使用。

```sh
python3 -m http.server 8895 --directory .
NODE_PATH=/opt/codex/cua_node/lib/node_modules \
  OUT_DIR=/tmp/english-quest-workshop-rng \
  node game/verification/workshop-rng/browser.cjs
```

`BASE_URL`（既定 http://127.0.0.1:8895/game/）、`CHROMIUM`（既定 /usr/bin/chromium）を上書き可能。依存のPlaywright/Chromiumは実行環境側に必要で、通常のnpm testには不要。

実際の工房画面で以下を確認。各操作後に保存→ページ再読込して倉庫と残金が一致し、pageerrorなし。

- 通常制作：400G＋通常素材4個を一度消費、ユニーク固有2〜4効果と有限値。
- 数値再抽選：800G＋粉10を一度消費、選択STRは有限値、MAGと効果種類/由来は維持。
- 全再付与：800G＋粉10を一度消費、エピックの規定3〜5効果・有限値。
- 強化：420G＋石I3個、+1。分解：キャンセルで無変更、確定で装備1個消費、既存の粉/石還元。
- 別の不足セーブで制作・全再付与・数値再抽選のボタンが無効。

初期の検証スクリプトは再読込後のタブ/折畳み状態と、粉還元の期待値を誤っていたため、実UIの初期状態・#167の還元式に合わせて修正した。ゲーム側の追加変更はしていない。最終スクリプトをそのまま実行し全確認成功。出力は指定ディレクトリのbrowser.json/workshop.png。

## 過去の破損装備

今回の変更は今後のボタン操作だけ。既存残金・粉・失われた抽選効果を推測で戻さない。保存済みのnullや空のaffixes/affixOriginsは通常再読込でも自動復旧しないことをテスト。以前からある旧形式制作品の移行処理も変更しない。正規の再抽選は新しい結果を抽選する操作で、過去の結果/費用の復元ではない。

実ユーザーのセーブ、全装備種類のブラウザ操作、全端末は未検証。合成セーブの代表装備と全既定テストで検証。D+条件やゲームバランス、破損装備の復旧は別件として変更していない。
