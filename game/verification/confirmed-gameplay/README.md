## 今回の実装

`docs/battle-system.md` §6 の決定済み挙動「直接攻撃を物理・魔法とも回避」「束縛中は不可」に対し、`attackDamage` の敵回避判定が物理だけに限定されていた。魔法技能と魔法武器の通常攻撃にも同じ判定を適用する。命中判定は既存どおり各対象・各ヒット。暗闇は物理のみ、状態異常専用技能は回避を通さない。回避した攻撃の付随異常は付かず、束縛中の回避は禁止する。

正式データ `elite_prefixes.csv` の `shadow` 回避率15%を維持。新しい職・技能・敵・係数・保存フィールドは追加しない。回避なしと束縛中は乱数呼出しも増えない。既存の魔法攻撃で回避持ちを攻撃した場合のみ、その後の乱数列は変化し得る。

固定ダメージ専用経路、予約攻撃の判定時点、反撃の物理限定、障壁、属性付与は今回の修正対象外。反撃の仕様本文と正式付与説明・既存テストの物理限定には不一致があり、一括で拡張しない。

計測を妨げていた `sim/party-fixtures.mjs` のAP0技能二重習得も修正。AP台帳作成により習得済みになる技能を再習得しない。ゲーム側の習得条件は変更しない。費用テストでは初期技能の0AP行を除いて実支払いを照合する。実装前後とも同じfixture修正を使う。

## 次に決めること

1. **推奨: 反撃・回避反撃の適用範囲を正式データと統一。** 魔法も対象にすれば仕様本文に一致するが既存説明・テスト・対魔法性能が変わる。物理限定を正式化すれば既存性能は保てるが仕様変更になる。行動1回と巡1回の上限も同時に明確化する。
2. **共通AP0技能の既存失敗。** `common_mana_afterglow` が未経験職判定に巻き込まれて装着できない。従来の全員初期技能として復元するか、取得経路を新設するか。推奨は元の共通初期技能の復元。新たな取得価格は創作しない。
3. **ジョブの次の1職。** 33候補から、解放元ID、AP・装着コスト、数値、奥義の承認を揃えたものだけを実装する。推奨は既存E01/E02で表現できる候補を先行し、汎用連携キューは後にする。
4. **世界移行。** 24地域・68行先のID対応とボス転用8体を決定した後、対策素材→制作→再挑戦の循環を確認する。ランク制限だけ先に外すと既存供給・解放を壊すため推奨しない。
5. **学習と出題。** 累積習得IDの永続条件と教材供給計画を先に決め、仮閾値の採否と試験範囲を決定する。周回の時間目標は6人・音声ありの実測と区別して決める。

- 未修正mainの全体テスト: 273件中267成功・6失敗。うちシミュレーションfixtureテストはファイル途中停止のため、修正後と総数が異なる。
- 今回の修正後: 283件中282成功・1失敗。残る `build-mechanics.test.js` の `common_mana_afterglow` 装着失敗は未修正mainでも再現した既存問題。全体成功とは扱わない。

- 既存fixture関連13件成功。36ビルドの核発動プローブは変更前36/36成功。
- `git diff --check` 成功。既存データID・CSV/JSON・セーブ構造は変更なし。モンスター総数1,024、6人編成を維持。
- ブラウザー手動プレイ、実時間、全行先・四季、長期成長／素材／経済、100候補・50職完成編成の計測は未実施。

### 計測の限界

単発プローブは正答100%・Lv20・6人で、通常敵と正式 `shadow` 修飾、開始時束縛の有無を比較する。敵HP・回避率を変更しない。選択した火魔法は初期技能である。敵と修飾の組合せは制御入力で、自然遭遇の到達性を表さない。制御場面の発動確認であり、shadowの出現率や勝率を示さない。

周回は `sim/README.md` の本体JS＋正式データ経路で18条件×80＝1,440遠征を各版で実行。事前育成・装備・道具を用意した固定方策であり、実際に準備するまでの収支・成長は再現しない。正答率は各問題の固定確率。勝った遠征の平均問題数を比較し、敗北の早期終了を混ぜない。自然発生の精鋭・賞金首を含むが、依頼受注効果は含まない。同じseedでも新たな回避判定により乱数消費が変わり、出来事の完全な対にはならない。基本・会心・弱点の3代表編成から全職の順位を推定しない。#47の未実装効果モデルは不使用。
