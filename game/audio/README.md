# English Quest のBGM

町・酒場・施設・ダンジョン・戦闘の5曲は、それぞれ約3分で一巡するオリジナルの編曲です。
旋律と和音を小節ごとに記述し、主題・副主題・静かな中間部・楽器を変えた再現部を設けています。
音色は波形から合成しており、外部の録音素材・既存楽曲のサンプリングは使用していません。

## 曲目

| ファイル | 使用場所 | 曲名 | 長さ | テンポ・拍子 | 編曲 |
|---|---|---|---|---|---|
| `town-square.mp3` | 町 | 旅立ちの広場 | 3:00 | 96 BPM・4/4 | 笛と撥弦、木陰のような静かな中間部、弦を加えた再現部 |
| `guild-tavern.mp3` | ギルド・酒場 | 灯火亭のワルツ | 3:00 | 96 BPM・3/4 | クラリネットと笛の受け渡し、暖炉のそばを思わせる間奏 |
| `town-facility.mp3` | 各施設・仲間・学習・記録 | 小さな工房の午後 | 3:00 | 80 BPM・4/4 | ベルと柔らかい弦、打楽器を使わない穏やかな曲 |
| `dungeon-depths.mp3` | ダンジョン探索 | 石の回廊と地下の光 | 3:00 | 80 BPM・4/4 | 短調の探索主題、明るい副主題、余白のある間奏 |
| `english-quest-battle.mp3` | 戦闘 | 遺跡を駆ける刃 | 3:00 | 128 BPM・4/4 | パルス音の主題、伸びやかな副主題、対旋律を加えた再現部 |
| `english-quest-victory.mp3` | 勝利演出 | Victory Fanfare | 約3.4秒 | 既存音源 | 短い演出として維持し、再生音量を新BGMに合わせる |

5曲の復号後の音長は180.000秒。MP3のコンテナにはエンコーダーの遅延・パディングがあるため、
`ffprobe` のコンテナ長はこれより数十ミリ秒長く表示されることがあります。
各曲は44.1 kHz・ステレオ・128 kbpsのMP3で約2.88 MBです。
音符の余韻と反射音を曲の先頭へ折り返し、末尾の属和音から冒頭へ戻る構成です。
再生機器・ブラウザによるループ継ぎ目の動作差までは保証しません。

## ゲーム内の再生

- 場面ごとに再生位置を覚え、施設の往復や戦闘の終了後も続きから再開します。
- ページ移動時の位置は同じタブの `sessionStorage` に記録します。ゲームのセーブや学習記録には混ぜません。
- 勝利ファンファーレは毎回先頭から再生し、終了後は現在の場面に戻ります。
- BGMのオン・オフ、英語の読み上げ中のミュートを維持します。
- 音声要素は1つで、その場面の曲だけを読み込みます。5曲の一括ダウンロード・デコードは行いません。
- 自動再生が制限された環境では、画面を操作すると再生を再試行します。
- 5曲のマスターは約−18 LUFS。再生音量は通常0.23、戦闘0.30、既存の勝利音源0.15です。

実装は `../js/battle-music.js`、関連テストは `../tests/battle-music.test.js` です。
音源と音楽モジュールのURLに `music-suite-1` を付け、更新前の短い音源のキャッシュと区別しています。

## 再生成

ゲームを動かすためのPython環境やビルドは不要です。音源を編集・再生成する場合だけ、
Python 3.10以降、NumPy、SciPy、FFmpeg（libmp3lameを含む）を使います。

```sh
# リポジトリのルートで実行
python game/audio/source/render.py --check
python game/audio/source/render.py --all

# 1曲だけ再生成する場合
python game/audio/source/render.py town-square
```

| ソース | 内容 |
|---|---|
| `source/peaceful_scores.py` | 町・酒場・施設の旋律、和声、曲構成 |
| `source/adventure_scores.py` | ダンジョン・戦闘の旋律、和声、曲構成 |
| `source/render.py` | 音色合成、ステレオ配置、循環する残響、音量調整、MP3出力 |
| `music-manifest.json` | 各曲の小節・曲構成・音長・音量・ファイルのハッシュ |

乱数を使う打楽器も固定シードで生成します。音楽的な内容は再生成で変化しません。
NumPy・SciPy・FFmpegのバージョンが異なる場合、圧縮後のバイト列やハッシュは変わる可能性があります。
レンダラーは小節の合計・音符の範囲・音量・曲の長さを検証してから書き出します。
`--all` は5曲を更新し、短い既存の勝利ファンファーレには触れません。

## 確認方法

```sh
npm --prefix game test
ffmpeg -v error -i game/audio/town-square.mp3 -f null -
```

再生位置の復元、メタデータの遅延、勝利演出中の移動、BGMオン・オフ、読み上げとの切り替え、
ページ移動・戻る操作、自動再生拒否、ストレージが使えない環境を自動テストで確認します。
ブラウザの音声出力や端末ごとの聴感は、ゲーム上で別途確認してください。
