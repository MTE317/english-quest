## ① 共通効果の契約

**決定済みの制約**は6人編成、状態異常20種、攻撃属性12種と相性5段階、武器16種、隊列・射程なし。各IDの正本は [状態](../data/status_effects.csv)、[属性](../data/elements.csv)、[武器](../data/weapon_types.csv)。既存の物理3・魔法9と、強弱点／弱点／等倍／耐性／無効を使う。強弱点は現行2倍、残りの非固定倍率はゲームデータを参照する。状態異常の耐性段階は攻撃属性の倍率とは独立する。ボスの石化・死の宣告免疫と既存の拘束制限を先に判定する。石化の勝敗判定・持ち越しと既存の勝利後回復を維持する。

**出題**はプレイヤーが通常手番で手動入力を確定するときに1問。通常攻撃・技能・手動の消耗品等は既存の出題導線に従う。敵、状態による強制行動、反撃・追撃、継続効果、予約済み攻撃、戦闘間効果からは出題しない。手動の予約入力には1問、後日の自動解決には0問。既存の [戦闘処理](../game/js/battle.js) の `prepareQuizAction` と `resolvePending` が接続点。

### タグとイベント（提案）

技の系列・対象・攻撃基準・段数・時間・費用・発生元を独立軸とする。傷を伴う全体武器攻撃なら攻撃と状態異常の両系列を持てる。タグは現行の `kind`、`effect_json`、装備、行動の出所から解決する。属性選択や副手はヒット実体に記録する。タグの参照式は全一致・いずれか一致・除外の3条件まで。同一タグの重複を除く。タグと処理名は検証時に登録制とし、表示名や旧別名は読込時だけ正規化する。

イベントは `battleId/round/rootActionId/actionId/hitId/depth/origin/actorId/targetId` と発生前後の差分を持つ。手動入力と正答確定 → 行動準備と費用確定 → 各ヒットの事前補正・命中・会心・吸収・HP反映 → 付与・回復・撃破 → 行動要約 → 派生キューの順。勝敗は同一起点の確定結果から判定し、勝敗確定後に戦闘用キューを破棄する。敵の予定行動と予約攻撃は既存の巡処理を使う。撃破、解除、障壁破壊は状態が遷移した瞬間に一度だけ記録する。命中と会心は同じヒットイベントで表現し、同系列の二重発動を防ぐ。

1ヒットは対象1体への1ダメージ計算。1行動は対象と段数を横断する起点1件。1巡は `startRound` で始まる既存の巡、1戦闘は固有の戦闘ID。各上限は効果所有者・効果グループ・該当スコープで集計し、複製スロットは同枠にまとめる。効果の成功時に消費し、キュー枠の予約は登録時に消費する。回避・異常連動などの1行動上限は相手の起点行動にも適用する。発動範囲と上限は共通効果JSONの14件を参照。

**連鎖防止の暫定値**は深さ1、起点ごとに派生2件、起点側パーティー（陣営ごと）で1巡6件、購読候補評価は起点64件。各対象イベントに決定的な順序を持たせ、優先度→所有者の巡順→技能IDで競合を解決する。派生はダメージ、状態、撃破を通常通り確定・記録できる。派生由来・持続ダメージのtickは新たな反応キューを出せず、E05のtick連動は上限内で術者資源を直接更新する。付与や資源変化で自分自身または同系列を再起動できない。途中で対象が倒れた派生は破棄。スロット番号は順序の同率解決にだけ使う。

### 補正順と初期値（提案）

現行の式を比較基準に、新しい条件付き与ダメージは同じ加算枠で合計し最大+30%。たとえば+10%と+15%は×1.25。会心倍率・属性相性・明示の防御軽減は既存の各乗算段階に1回ずつ適用。命中・会心・付与の率補正は各段階で加算して既存の上限へクランプし、免疫は最優先。MP軽減は新規枠−20%まで、非無料技能の最終費用は最低1。基礎威力とDEF/RESを確定してから命中、属性、会心、軽減、障壁、MP肩代わり、HP反映を処理する。途中の小数は保持し、実リソースの取引確定で丸める。既存の丸めや既存効果との重複は移行比較の対象。

| 対象 | 暫定の投入値 |
|---|---|
| 条件付き火力 | 単一条件+10〜15%、異常種類数は1種ごと+5%で3種まで |
| 味方反応 | 次行動+10%、受け手1巡1回。派生攻撃を扱う際は主攻撃相当の30%から |
| 会心・回避MP | 1回1〜2MP。1行動1回。譲渡・反転で生じたMPは再変換対象外 |
| 小障壁 | 最大HPの5〜8%、累計上限25%、持続2巡。上書きは高い残量を優先 |
| 溜め | 次の適格単体技+25%を出発点とし、2手合計で通常2手と比較。防御・治療で消費しない |
| HP・MP変換 | 被ダメの25%を上限にMPへ1:1で肩代わり。残MP不足分はHPへ。攻撃側の能力参照は元能力の最大20% |
| 戦闘間補給 | 勝利後1回、HP/MPのうち片方を最大値の5%まで。既存回復と合算して測る |

多段・複数敵の生イベントはヒット数に比例する。E07の購読はイベント種別・陣営で索引し、根の行動要約で1度だけ評価する。仮に6人が3対象へ4ヒットし残り5人が毎ヒット購読すると候補通知は360件/巡。要約なら30件、派生最大6件。これは [独立した件数モデル](../sim/results/build-design-controlled.json) の結果。実ゲームのフレーム時間・新効果の勝率は未計測。実装後は候補評価数、実発動、上限破棄、出題、ログ件数、巡解決時間のp95を記録する。

## ③ ジョブ割当と習得

**提案は50職**。既存14職の技能・奥義IDを保持し、自己完結の専門役36職を追加候補に置く。計画武器で16種、担当属性で12種、付与・解除・対策の担当で20状態をカバーする。75と93–96は保留なので各専用職を先に増やさない。担当ビルド番号は技能設計の優先範囲。主担当以外は組み合わせの用途で、全機構を各職単独で供給する想定ではない。

追加職は自由習得。AP・装備枠と技能コストが機会費用。一般技能は習得後に他職でも装着でき、使用時の武器・資源条件は維持する。固有奥義は現職のみ。既存14職の取得条件は現行データを維持し、追加36職は個別の依頼・調査・制作の達成条件で開放する。ジョブの昇格や他職の修了を共通前提にしない。状態を参照する通常パッシブも、別職や味方で付与できるため前提技能なし。明示的な連携技能を追加する際だけ、対応トークンを生成する行動へのアクセスを前提にできる。

基本職が終盤でも役割を保つ。戦士は即時単体火力、ナイトは軽減・かばう、黒魔道士は直接範囲、白魔道士は即時回復・蘇生、盗賊は調達、武闘家は連打、狩人は弱点調査、吟遊詩人は安定した全体支援。追加職の条件付き強化には準備時間や耐性などの不利を残し、追加職共通の能力値上昇は導入しない。実装比較は同レベル・装備・技能装着予算で行う。

### 次に決める事項

1. 弱点編成の★12標準・深層での短縮幅が、大半の敵に対して恒常的に出るか。同じ6人で属性、装備、方策を一要因ずつ替えて切り分ける。
2. 短期型・単体ボス型・多数敵型で、準備に使う手番と出題増を何問まで許容するか。6人の問題数目標を従来4人の比較値から分けて決める。
3. E01/E02を既存補正へ接続し、E03–E06・E11を単発／多段／全体で追試してからE07の購読を有効にする。味方連携の上限、勝利後回復、盗み・撤退の経済影響はその段階で見直す。
4. 新職のAP・装着コスト、解放報酬の具体的な依頼ID、奥義の相対威力を決める。保留5件は仕様の追加コストを確認して別工程で採否を決める。
