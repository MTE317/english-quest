# バランス調整レポート

## 1. 今回の調整で目指した体験

短い冒険を繰り返し、そのたびに技能・装備・編成を試せる形へ調整した。通常戦は一戦15〜20問、標準ダンジョンは通常二戦とボス一戦で約5〜7分を設計目標とした。ユーザーが示した約70%は、適正な育成と装備で挑む**標準ダンジョン一周の踏破率**として扱った。通常戦一戦ごとに30%負ける設定ではない。

ボスに合わせて耐性や弱点、役割分担を考えた編成には、大きな利点を認める。職名だけで一律にダメージを増やす方式を整理し、武器の特性、技能の持ち出し、状態異常、耐性、付与効果が実際の戦闘で組み合わさるようにした。モンスターの総数は**1,024体を固定**し、遭遇の重みと戦闘式を調整した。

掲示板・初期資金・中級職の解放も、ビルドを試すための入口として扱った。初期1,000Gは買い物と補給を選ぶ余裕に充てる。比較用の制作済みパーティと、初期装備から育てるプレイヤーの進行は別に検証する。

実測結果は条件ごとに示す。目標の数値を、そのまま達成済みの結果として記載しない。

## 2. 設計目標

設定の正本は [`data/balance.json`](../data/balance.json) の `balance_targets`。一巡は、生存して行動可能な仲間が順に行動するまとまりを指し、4人が行動すれば通常4問になる。

| 項目 | 目標・判断基準 |
|---|---|
| 通常戦一戦 | 15〜20問、およそ4〜5巡 |
| ボス一戦 | 20〜25問を目安とし、対策と消耗で差を出す |
| 標準ダンジョン | 50〜65問、約5〜7分 |
| 基準の正答率 | 80%。65%・95%の条件も別に確認する |
| 標準の踏破率 | 約70%、検証上の目標範囲65〜80% |
| 相手に合わせた準備後 | 85〜95%を目標。大きな改善を許容する |
| 成長の間隔 | 成功した冒険2〜3回で、レベル・技能・装備のいずれかに進展 |

時間は **問題数×6秒＋30秒** で換算する。6秒には回答に伴う操作や演出を含める仮定を置き、30秒を追加の操作時間としている。ブラウザ上で人が遊んだ時間の実測ではない。読み上げを待つ時間、意味を考える時間、編成や装備を選ぶ時間によって変わる。

## 3. 冒険の長さとモンスターの見せ方

### 遠征を短くし、挑戦の長さを選べるようにした

60ダンジョンの新しい配置を、1階1戦・合計204階／204戦へ整理した。ボス到達時の想定敵レベルは旧配置との連続性を保ち、戦闘回数だけを減らして報酬を何倍にもすることがないよう、一周の収入予算も配分し直した。

| 種類 | 戦闘構成 | 消費日数 | 帰還ポイント |
|---|---|---:|---|
| 近場 | 通常1戦＋ボス1戦 | 1 | 1階の後 |
| 標準・素材の宝庫・季節の地 | 通常2戦＋ボス1戦 | 2 | 2階の後 |
| 深層 | 通常5戦＋ボス1戦 | 3 | 3階の後 |

通常戦は初階2体、次の通常階から3体。ボス戦はボスと取り巻き一体。短い遠征でも全体攻撃、単体への集中攻撃、MPを残す通常攻撃を使い分けられる構成にした。

### 1,024体を維持し、地域でよく見る敵を決めた

内訳は通常663・季節240・ボス60・賞金首48・闘技場専用13。総数と既存IDを維持したまま、地域の常連6種へ基本抽選重みの80%を配分した。残りの候補にも重みを残すため、通常・季節の903種を抽選候補から削除していない。季節は「季節の地」以外にも適用する。

同じ戦闘での同種の連続抽選を抑え、旧セーブの個別種討伐が残っている場合は対象の重みを上げる。したがって80%は基本の配分であり、補正後のすべての遭遇で固定される実測比率ではない。全通常種・季節種の到達可能性は地域と四季を走査するテストで確認する。

エリートは★2以降の通常戦で6%の抽選、一戦・一周とも最大一体。最終ボスや賞金首と重ねて急激に難しくしない。賞金首は道中の通常敵一体と置き換え、対象依頼の受注中は一周の出現率を40%にする。未受注時の自然出現も残している。

## 4. ボスとビルドが機能するための補填

### ボスは予告に対応できる相手にした

ボスの周期的な全体攻撃を前の巡から表示する。現在の基本設定は三巡ごとに全体攻撃、一巡前の予告。ダメージの軽減、回復、攻撃を終える順番を選ぶ意味を持たせた。予告と実際の行動は同じ判定関数を使う。

毒・出血・弱体化もボス攻略に使える一方、行動封じを繰り返すだけで倒せる状態を抑えた。ボスへの状態異常と行動封じには別の付与補正を設け、行動封じの再使用では付与率を下げ、直後の連続拘束も制限する。石化と死の宣告の個別無効、継続ダメージの軽減と合計上限も設定した。数値の正本は `battle_formulas` にまとめている。

### 効果の名前と実際の発動をそろえた

- `DOT_POWER` は毒・出血などの継続ダメージを強める。付与者の装備・パッシブの強化を付与時に保存する。`STATUS_RATE` は状態異常を付ける成功率を補助する。
- `VS_DEBUFFED` は、状態異常だけでなくDEF低下などの弱体を受けた相手への直接ダメージにも適用する。
- 二刀流の副武器攻撃は通常攻撃時だけ。副武器の固定状態異常も、その武器の通常攻撃が当たった場合に判定する。
- 追撃と装備による通常攻撃MP回復は一行動一回まで。HP吸収は実際に減らしたHPから計算し、一行動の回復量にも上限を設ける。
- 反撃は物理被弾時だけ。反撃を起点に追加状態異常・追撃・吸収を連鎖させない。
- 剣気は武器の攻撃属性を、選んだ魔法属性一つへ切り替える。弱点への追加補正が正しく働くようにした。
- 扇は全体強化を伸ばす。歌の持続延長は吟遊詩人の全体強化、舞の持続延長は踊り子の全体強化へ適用する。
- 「励まし」は自分のMPを仲間へ分ける処理とし、技能の消費に加えて渡したMPも本人から減らす。吸魔の回復も消費MPを超えない扱いにした。

会心、回避、軽減、耐性、付与率などにも上限を置いた。これらは組み合わせを弱くする一律補正ではなく、確率や連鎖が無制限に積み上がる経路を閉じるための制限である。

公開14ジョブの `dmg_mul` は1.0へ統一した。以前の職別2〜3倍の値は、本体JSに接続されていない旧シミュレーター側の補正だった。今回の強さは、能力値・適性・武器特性・技能・装備の組み合わせで比較する。

### 用意した8系統

具体的な技能・制作レシピ・付与素材は、ゲーム内「仲間 → ビルド手引き」と [`docs/build-guide.md`](build-guide.md) にまとめた。以下は選ぶ際の要約であり、全案が同じ敵に同じ強さを持つという順位表ではない。

| 系統 | 主な組み合わせ | 強み | 苦手な場面 |
|---|---|---|---|
| 毒刃 | 盗賊・毒短剣・毒刃・付与率／継続ダメージ | 守りながら削る。薬師・呪術師の技能を持ち出して発展 | 毒に強い敵、準備する前に終わる短期戦 |
| 出血鎌 | 戦士または呪術師・鎌・血風・弱体特効 | 出血と直接攻撃を併用。敵が多い場面にも対応 | HP消費と被害が重なる場面、状態異常や弱体を入れられない相手 |
| 会心二刀 | 盗賊・刀／短剣・心眼・会心率／会心ダメージ | 通常攻撃の手数と会心向け技能を使い分ける | 会心の不発、防御を削りすぎた編成 |
| 弱点狩人 | 狩人・弓・狙い撃ち・剣気・弱点／種族特効 | 行き先の弱点と種族を調べた準備が効く | 有効な弱点を突けない相手 |
| 耐性反撃 | ナイト・鎚／剣・反撃の構え・耐性／軽減 | 被害を抑えながら物理攻撃へ反撃する | 魔法中心の相手、回復の追いつかない集中攻撃 |
| 属性魔法剣 | 魔法剣士・剣／鎌・剣気・剣と魔の心得 | 属性を選び、STR・武器・MAGを組み合わせる | 属性の選び違い、準備の一手とMP負担 |
| 全体支援 | 吟遊詩人／踊り子・楽器／扇・歌／舞 | 仲間の攻撃と守りをまとめて伸ばす | 攻撃役が少ない編成、支援だけを重ねすぎる操作 |
| 回復循環 | 白魔道士・杖・回復強化・MP節約／通常攻撃MP回復 | 必要な回復量を確保し、余裕のある手でMPを戻す | 毎手回復が必要な被害、回復役の行動不能 |

武器16種、専用制作153件は維持した。中級職をまだ解放していなくても手引きは読めるが、隠し上級職は掲載しない。並行作業の防具アイコン差分も統合し、町・工房・仲間画面で既存の武器画像とともに表示する。

## 5. お金・依頼・成長の間隔

### 六つの依頼から、今の冒険に合うものを選ぶ

未受注の掲示枠を6件にし、受注枠とは分離した。同時受注は初期3件、★4で4件、★8で5件。討伐・採集・ボス・賞金首を混ぜ、現在の季節と行き先で達成できる対象を生成する。通常討伐は地域の魔物3〜5体、採集は地域の通常素材2〜3個とし、短い遠征にも合う条件へ変えた。

通常依頼は無料。賞金首だけ、掲示報酬の10%を受注時に預ける。達成報告では報酬とは別に全額返還し、自主放棄は預かり額の80%を返還する。保証金は切り上げ、放棄時の返還は切り捨て。全滅・撤退で契約を自動失敗にせず、期限も設けない。

受注中の依頼、手元の所持金、預かり保証金、行き先、報酬、進捗を表示した。受注・報告後は候補を補充するが、同じ内容の依頼は次の帰還まで再掲しない。受注と放棄を繰り返す再抽選や、同じ在庫での無制限な報告を抑える。達成・放棄後は契約を取り除き、二重返金も防止する。

### 1,000Gと、制作済み比較編成の費用は分ける

新規開始の共有資金は1,000G。既存セーブの資金へ一律加算はしない。一周収入は戦闘数に対応して配分し、宿・消耗品・制作・付与・会費のどこへ使うかを残した。

検証に使う「標準装備」は、初期配布装備の意味ではない。比較用編成は、その等級で仕様上用意できる制作装備・技能・施設を準備した状態である。基本4人分の全身通常制作28品だけでも、通常素材112個と制作費が必要で、さらに付与素材・費用、強化、技能のAP等がかかる。**初期1,000Gで比較用の完成装備を直ちにそろえられる、という測定ではない。** 初期装備からの進行は追加結果の初期導線検証で扱う。

### 技能は数回の成功で一つずつ進める

通常戦のAPを2、ボス戦を4とした。標準ダンジョンで通常二戦とボスを倒し、各戦闘を生存して終えたメンバーは、基本で **2＋2＋4＝8 AP／周** を得る。APは現在のジョブに入る。途中で倒れたメンバーや、賞金首を含む周では結果が変わる。

| 技能の必要AP | 8 APずつ得る場合の必要成功周数 |
|---:|---:|
| 10 | 2周 |
| 20 | 3周 |
| 30 | 4周 |
| 45 | 6周 |

これは一つの技能の費用を0 APからためる場合の計算で、未習得の前提技能の費用は別に必要。全滅した周のAPを持ち帰れる計算でもない。序盤の小さな技能、レベルアップ、素材を集めての制作を組み合わせ、「2〜3回で何かが進む」目標へ近づける。

発見型の公開中級職には回数保証を追加した。魔法剣士は崩れた砦、精霊術士は風鳴りの峡谷で、ボス撃破時10%の早期発見を残し、3回目の踏破までに発見する。既存の踏破数を引き継ぎ、全滅や途中帰還は加算しない。神殿に発見先と現在回数を表示する。

## 6. 標準ダンジョンの検証方法

今回の戦闘測定は [`sim/balance.mjs`](../sim/balance.mjs) から実ゲームの `game/js/battle.js` を呼び出す。別の戦闘式を持つ旧Pythonモデルの結果を今回の測定と混ぜない。

| 条件 | 内容 |
|---|---|
| 対象 | ★1〜★12の標準ダンジョン各一か所 |
| 編成 | 戦士・ナイト・黒魔道士・白魔道士 |
| 比較 | 標準の制作装備と、相手に合わせて属性・状態耐性等を準備した装備 |
| レベル | 各ダンジョンの敵レベルの平均を丸めた値を出発時に設定 |
| 技能 | 等級に応じた習得段階。前提技能・装備枠・奥義の持ち出し制限を通す |
| 装備 | 同じ素体レベルと品質1.15、同じ強化段階（等級に応じて+0〜+3）で比較 |
| 制作・付与 | 実際の `craft`・`enhance`・`enchant` と装備可否の判定を通す。必要資源は比較用に供給し、組立費用を別に記録 |
| 正答 | 各行動で確率80%の正答を生成。実際の単語選択や記憶モデルの測定ではない |
| 季節 | 春 |
| 敵 | 通常の遭遇重み、エリート、未受注状態の自然な賞金首出現を含む |
| 道具 | 有限の持込品を戦闘中・戦闘間とも消費。無限回復は行わない |
| 操作 | 固定ルールのAI。弱点は既知。未来の乱数を参照せず、撤退しない |
| 経験値 | 学習報酬倍率1.0。戦闘中の獲得とレベルアップを反映 |
| 収支・ドロップ | 戦闘報酬だけ。クエスト報酬・月末会費は除外。素材・装備はバックパック選別前の落下数 |

比較用編成の作成は [`sim/party-fixtures.mjs`](../sim/party-fixtures.mjs) にまとめた。制作・付与・習得手続きを正しく通すことと、必要な全資源をその時点までの冒険で実際に稼げることは、検証上別の問いである。AP・JP・施設・素材を準備した編成比較から、初期導線の経済性を推定しない。

AIは蘇生・回復・一部の状態異常治療・強化・弱体・弱点攻撃を使い分けるが、全状態異常の完全な治療や、全ビルドでの最適な行動順序を保証しない。人が予告を見て的確に守る場合にも、逆に操作や判断に迷う場合にも、そのまま一致する勝率ではない。

## 10. 検証の範囲

単体・統合テストでは、地域と四季の遭遇可能性、短縮経路と帰還、賞金首・エリートの重なり、報酬配分、掲示と保証金、発見保証、戦闘効果、比較用編成の合法な手続き、既存セーブの移行を確認する。

手引きは8案すべての参照ID、技能の装備枠、付与先と素材の組み合わせを検証した。DOM操作で一覧・詳細・ジョブ絞込・戻る操作を確認し、武器・防具の画像参照と構文も確認している。実Chromiumの起動は環境のソケット制約で使えなかったため、実画面のスクリーンショットによる見た目の確認は未実施。

最終のローカル実行では `npm --prefix game test` の **182テストがすべて成功**した。56個のJS/MJSの構文、62件のデータmanifest、HTMLとモジュールの参照先も確認し、欠落はなかった。モンスター1,024件のIDと並び順を変更前と照合し、全件一致を確認した。60ダンジョン・204階層のデータも検査した。

## 11. この結果でまだ言い切れないこと

**標準の比較は、初期装備の難度を表さない。** 作成費用を記録した合法な編成でも、素材・AP・工房の準備は省略している。新規開始からの遊びやすさは、初期導線の別測定と合わせて判断する必要がある。

**一条件の試行数には幅がある。** 各★80回の勝率は1回で1.25ポイント変わる。80回全勝でも、別の試行や操作で負けないことを意味しない。95%区間は試行のばらつきの目安であり、AIの方策、装備の選択、未知の敵や季節など、測定していない条件差まで含む保証ではない。

**収支は一周の一部を測っている。** `netGoldBeforeFees` は成功周の戦闘収入から、使った道具の補充相当額と安い宿代を差し引いた値。クエスト報酬、月末会費、借金・利息、制作・付与の初期費用、神殿での追加処置、装備売却は含めない。素材・装備の数もバックパックで全量持ち帰れた数ではない。全滅時はゲームのルールに合わせ、戦闘報酬と消耗品の支出を出発前へ戻す。

**学習全体の完了時間は測っていない。** 現在の単語教材は90語で、詠唱は別教材。15,000語の収録とSランク到達までの年数は将来構想・旧長期モデルの話であり、今回の実ゲーム戦闘を再校正した結果として流用しない。復習の質による経験値補正も、この基準測定では1.0に固定している。

個体・編成の組み合わせは多い。1,024体の到達可能性や効果処理のテストが通ることと、すべてのボス・賞金首・闘技場・全編成の難度を均等に測定済みであることは別である。今後の追加調整では、実際のプレイで困った敵・行き先・ビルドを特定して、その条件を再測定する。
