# ゲーム側（Claude Code）からのお願い・質問

ゲームを作っていて見つけた、足りない項目や決めてほしいことです。
決まるまでは、ゲーム側で仮の値を使っています（仮の値はすべて `game/js/srs.js` の `FALLBACK` の1か所にまとめてあり、`data/srs.json` に項目が入ればそちらが優先されます。データ確認画面でも「srs.json にない項目」として表示しています）。

## 2026-11-21：学習記録と4択の問題を作ったとき

### srs.json に足してほしい項目

| 項目名（案） | 仮の値 | 内容 |
|---|---|---|
| `fsrs_w` | FSRS-5 の公開されている初期値（19個） | 復習の間隔の計算に使う FSRS のパラメータ |
| `maximum_interval_days` | 36500 | 復習の間隔の上限（日） |
| `learned_streak` | 3 | 「日を空けて3回続けて正解したら習得」の 3（今は `learned_rule` に文章でしか書かれていない） |
| `learned_min_gap_days` | 1 | 「日を空けて」の日数。同じ日に何度正解しても1回分として数えている |
| `familiar_streak` | 1 | 誤答の選択肢を「別の石から」→「同じ石の似た単語から」に切り替える基準（その単語を日を空けて続けて正解した回数） |
| `retry_gap` | 3 | 1回の遠征の中で、間違えた単語をもう一度出すまでにはさむ問題数 |

### 決めてほしいこと

1. **`new_per_run: [10, 15]` の下限の 10 の使い方**：今は「1回で初めて出す単語は最大 15 語（かすれたルーンが `reduce_new_when_due_over` を超えたら `reduced_new_per_run`）」として、下限の 10 は使っていません。下限の意味（例：かすれたルーンの数に応じて 15→10 に減らす、など）を決めてほしいです。
2. **復習の日数は現実の日付で数えています**（ゲーム内の暦ではない）。記憶は現実の時間で薄れるためです。この考え方でよいか確認したいです。日付の切り替わりは端末の時刻の0時にしています。
3. **習得した単語を間違えたとき**：今は「学習中」に戻し、連続正解数を 0 にしています。習得のままにする（かすれるだけ）ほうがよければ教えてください。
4. **間違えた単語の次の復習**：FSRS の計算に関係なく「次の日」にしています（FSRS の再学習にあたる部分）。
5. **「似た単語」の決め方**：今は lexicon.csv の列だけで、つづりの近さ（編集距離）・同じ kind・同じ pos・日本語の語尾（「〜する」「〜な」）で点数をつけています。意味の近い単語（類義語）や、間違えやすい組み合わせを出したいなら、lexicon.csv に `similar`（`|` 区切りの ID）のような列があると助かります。
6. **正誤の記録**：今は単語ごとに正解数・不正解数だけを保存しています（15,000語で1MB未満に収めるため）。1回ごとの記録（日時・問題の形・選んだ答え）が必要なら教えてください。

### データについて

- `targets.csv`・`balance.json`・`srs.json` は BOM がついていません（README では「BOM つき」）。ゲームはどちらでも読めるので困ってはいませんが、念のため。
- lexicon.csv の `pos`・`example_en`・`example_ja` がまだ空です。品詞が入ると「似た単語」の精度が上がり、例文が入ると資料室の予習カードやフレーズの空欄埋めが作れます。
- GitHub Pages ではフォルダの中身を一覧で取れないため、データ確認画面は `game/js/manifest.js` に書いたファイル名の一覧で読んでいます。`data/manifest.json`（ファイル名の配列）があれば、ファイルが増えたときに自動で読めるようにできます。
