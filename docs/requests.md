## 2026-11-22：ダンジョンを作ったとき

### data に入れてほしいもの

`balance.json` や CSV に数や式として書かれていないものは、シミュレーター（`sim/world.py`）と同じ値を `game/js/loot.js` の `LOOT_FORMULAS` に置いて使っています。

| 項目 | 今使っている値（sim と同じ） |
|---|---|
| 敵1体のお金 | `run_income × income_mul × gold_share ÷ 27 × 乱数(0.8〜1.2)`、ボスは `boss_gold_mul` 倍（`gold_per_enemy` の「(boss x boss_gold_mul)」が文） |
| ボスの素材 | ふだんの素材1〜2個、まれな素材30% |
| 落ちる装備の部位 | 武器35%・頭体腕45%・マント8%・アクセサリー12% |
| 落ちる装備の Lv | ダンジョンの item_lv_min〜max のうち、奥の階ほど高い |
| レアリティの重み | レア以上は ×(1 + 0.08×(階-1) + 0.15×(★-1)) |
| ランダム効果の大きさ | min〜max。scales_with_item_lv なら ×(1 + 装備Lv/12)、アーティファクト以上は ×1.15 |

### 決めたこと（違っていたら教えてください）

- ダンジョンに入るときに `days` の日数を進めます（全滅したら戻る）。
- 「逃げた」戦闘も1戦として数え、先へ進みます（sim と同じ）。
- 帰還ポイントは `dungeon_floors.csv` の `return_point_after` が1の階のあと。そこで「町に帰る」か「先へ進む」を選びます。
- 戦闘の外（戦闘と戦闘のあいだ）でも回復の道具は使えます（問題は出ません）。強くなる手段ではなく、減ったものを戻すだけなので。
- 持っていける石は「★がダンジョン以上」だけ確かめています。「今の★の石を全部読んだら1つ上の★も」（`stones_ahead`）は資料室（チェックリスト10番）で予習を作るときに入れます。
- 季節で入れかわるモンスター（role が season）は、1か月の日数が決まってから入れます。強い個体の出現（8%）と賞金首はチェックリスト13番で入れます。
- 「盗む」「見極め」（utility）はまだ使えません。効果を `effect_json` に書いてもらえると作れます（例：`{"steal": 0.5}` / `{"reveal": true}`）。

### バランスについて（参考）

ゲームの戦闘で、苔むした洞窟を「正答率80%・パーティは通常攻撃だけ・白魔道士だけ回復」で100回ずつ遊ばせると、Lv1 では一度も踏破できず（3階でほぼ全滅）、Lv7前後で約9割が踏破しました。敵の式は sim と同じです。sim の遊び方（戦闘のあいだの回復・危ないときは帰還ポイントで帰る・戦闘のあとの MP 回復＝共通パッシブ）を入れると変わるはずなので、チェックリスト9番（共通ツリー）のあとで見直すとよさそうです。

## 2026-11-22：戦闘を作ったとき

### balance.json に式として入れてほしいもの

`balance.json` に説明の文しかない式は、シミュレーター（`sim/battle.py`・`sim/core.py`）と同じ式を `game/js/battle.js` の `BATTLE_FORMULAS` に写して使っています。

| 項目 | 今使っている式（sim と同じ） |
|---|---|
| 敵の DEF / RES | `(6 + 3.2*Lv) * def_mul` / `(6 + 3.2*Lv) * res_mul`（今の `def_res` は「def_mul / res_mul」と2つが1つの式に入っている） |
| 味方の与えるダメージ | `(能力値 + 武器の攻撃力) × 倍率 × 属性 × 100/(100+防御) × 会心 × 乱数(0.95〜1.05)` |
| 敵の与えるダメージ | `STR(またはMAG) × 1.62 × 100/(100+DEF または RES) × 乱数(0.9〜1.1)`（`damage_to_party` は文が混ざっていて計算できない） |
| 回復の量 | `(MAG + 武器の攻撃力) × 倍率 × 杖なら1.15` |
| 爆薬投げ（fixed_damage） | `(20 + 6*武器Lv) × 属性 × 100/(100 + RES×0.3)` |
| 逃げる確率 | `max(0.10, min(0.95, 0.5 + SPD差×0.01 + LUK×0.002 + Lv差×0.02))`（ボス戦と束縛中は0） |
| 経験値 | `6 + 3.2*敵Lv`、ボスは×5（`xp_per_enemy` の「(boss x5)」が文）。強い個体は reward_mul 倍 |
| 経験値の減り方 | `max(0, 1 - 0.25 × max(0, (自分のLv - 敵のLv) - 1))`（`overlevel_penalty_per_level` が文） |
| 行動順の乱数 | SPD × 0.9〜1.1 |
| 挑発の重み | 狙われやすさ 1 + taunt×4 |
| ボスへの状態異常 | 確率×0.3、同じものを重ねるたびに半分。石化と死の宣告は効かない |

### weapon_types.csv に列があると助かるもの

説明の文（feature）にしか書かれていないので、sim と同じ値を `WEAPON_TRAITS` に置いています。

- 通常攻撃が魔法になる武器（杖・魔導書・楽器）
- 杖の回復×1.15、魔導書の MAG×1.1、銃の STR×0.5、鞭の「全体に×0.5」

### そのほか

- スキルの `st` にある「DEFダウン」は `status_effects.csv` にないので、sim と同じく「DEF -25%・3ターン」にしています。
- 状態異常を治せる道具・スキルは、`status_effects.csv` の `cure` 列に書かれた名前で決めています（例：毒は「毒消し・万能薬・清めの光」）。名前を変えるときは両方を合わせてください。
- 戦闘で使えるスキルは、今はジョブの1段目（`ap_to_learn` が0）だけです。スキルツリーと AP はチェックリスト9番で作ります。「盗む」「見極め」（utility）はダンジョンを作るときに足します。

### balance.json に式として入れてほしいもの

今はシミュレーター（`sim/core.py`）の式をゲーム側（`game/js/character.js` の `SIM_FORMULAS`）に写して使っています。`balance.json` に計算できる形で入れば、そちらを使うようにします。

| 項目 | 今使っている式（sim と同じ） | 備考 |
|---|---|---|

## 2026-11-21：学習記録と4択の問題を作ったとき

**→ `docs/checklist.md` 5章で回答をもらい、ゲームに反映しました（2026-11-22）。**

### srs.json に足してほしい項目

| 項目名（案） | 仮の値 | 内容 |
|---|---|---|
| `fsrs_w` | FSRS-5 の公開されている初期値（19個） | 復習の間隔の計算に使う FSRS のパラメータ |
| `maximum_interval_days` | 36500 | 復習の間隔の上限（日） |
| `learned_streak` | 3 | 「日を空けて3回続けて正解したら習得」の 3（今は `learned_rule` に文章でしか書かれていない） |
| `learned_min_gap_days` | 1 | 「日を空けて」の日数。同じ日に何度正解しても1回分として数えている |
| `familiar_streak` | 1 | 誤答の選択肢を「別の石から」→「同じ石の似た単語から」に切り替える基準（その単語を日を空けて続けて正解した回数） |
| `retry_gap` | 3 | 1回の遠征の中で、間違えた単語をもう一度出すまでにはさむ問題数 |

### 決めてほしいこと

1. **`new_per_run: [10, 15]` の下限の 10 の使い方**：今は「1回で初めて出す単語は最大 15 語（かすれたルーンが `reduce_new_when_due_over` を超えたら `reduced_new_per_run`）」として、下限の 10 は使っていません。下限の意味（例：かすれたルーンの数に応じて 15→10 に減らす、など）を決めてほしいです。
2. **復習の日数は現実の日付で数えています**（ゲーム内の暦ではない）。記憶は現実の時間で薄れるためです。この考え方でよいか確認したいです。日付の切り替わりは端末の時刻の0時にしています。
3. **習得した単語を間違えたとき**：今は「学習中」に戻し、連続正解数を 0 にしています。習得のままにする（かすれるだけ）ほうがよければ教えてください。
4. **間違えた単語の次の復習**：FSRS の計算に関係なく「次の日」にしています（FSRS の再学習にあたる部分）。
5. **「似た単語」の決め方**：今は lexicon.csv の列だけで、つづりの近さ（編集距離）・同じ kind・同じ pos・日本語の語尾（「〜する」「〜な」）で点数をつけています。意味の近い単語（類義語）や、間違えやすい組み合わせを出したいなら、lexicon.csv に `similar`（`|` 区切りの ID）のような列があると助かります。
6. **正誤の記録**：今は単語ごとに正解数・不正解数だけを保存しています（15,000語で1MB未満に収めるため）。1回ごとの記録（日時・問題の形・選んだ答え）が必要なら教えてください。

### データについて

- `targets.csv`・`balance.json`・`srs.json` は BOM がついていません（README では「BOM つき」）。ゲームはどちらでも読めるので困ってはいませんが、念のため。
- lexicon.csv の `pos`・`example_en`・`example_ja` がまだ空です。品詞が入ると「似た単語」の精度が上がり、例文が入ると資料室の予習カードやフレーズの空欄埋めが作れます。
- GitHub Pages ではフォルダの中身を一覧で取れないため、データ確認画面は `game/js/manifest.js` に書いたファイル名の一覧で読んでいます。`data/manifest.json`（ファイル名の配列）があれば、ファイルが増えたときに自動で読めるようにできます。
