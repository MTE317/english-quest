## 設計の優先順位

1. 承認された新合意を設計の正本とし、このディレクトリに反映する。記述が食い違う箇所は、この仕様を既存の [ゲーム概要](../game-overview.md) や関連資料より優先する。
2. 詳細設計の出典には [戦闘仕様](../battle-system.md)、[ビルド拡張設計](../build-expansion-design.md) などを使う。詳細資料の提案は、承認されるまで提案として扱う。
3. 実装の現状は main のコード・データを根拠とする。確認基準は [main のコミット 72279ea](https://github.com/MTE317/english-quest/commit/72279eade9275c97f3a63c0261ab85e4ec738e8e)。[PR #44](https://github.com/MTE317/english-quest/pull/44) と [PR #45](https://github.com/MTE317/english-quest/pull/45) は確認時点で未マージ。

## ステータスの読み方

| 軸 | 表記 | 意味 |
| --- | --- | --- |
| 設計 | 確定 | 合意済みの方針または制約 |
| 設計 | 仮決定 | シミュレーションや実装検証の初期値・初期案。結果に応じて変更する |
| 設計 | 保留 | 決定を見送った事項。条件を満たした後に再検討する |
| 実装 | main 実装済み | 確認基準のコードまたはデータで裏づけられる範囲 |
| 実装 | PR 実装・未マージ | 作業ブランチで確認した範囲 |
| 実装 | 未実装／未確認 | v1.0との差分が残るもの／現状の裏づけが取れていないもの |

「構想」「設計目標」は完成時の範囲を示す。データ行数、候補ビルド、PRでのテスト結果は、それぞれ別の根拠として扱う。

## 設計の依存関係

- 地図の発見・入場条件と季節が、行き先、掲示候補、敵・素材供給を決める。
- 帰還・全滅時の保存境界が、宝箱・発見・依頼達成・費用・奉納の確定に影響する。
- 敵・素材・制作・ジョブ・装備の参照をつなぎ、6人編成の育成と周回収入を同じ条件で検証する。
- 学習と探索は独立して進められる。昇格だけが累積習得・冒険実績・ギルドポイントに依存する。

プレイヤー向け表示とPR説明では、未発見の地域・ボス・ジョブの存在や名称が漏れないようにする。開発文書の参照は `1-A`、`E1`、`X` などの中立IDを優先する。
